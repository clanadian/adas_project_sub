# PS 요청 — conv0 pre-pad 버퍼의 행 스트라이드 294 → 296 바이트

**작성:** 2026-08-19 · **보낸 쪽:** PL (HLS/Vivado/검증) · **대상:** PS
**요청 규모:** 버퍼 한 개의 행 정렬 · **기대 효과:** 프레임 **약 4%** (12.86 → 약 13.4 FPS)

## 한 줄 요약

96×96 ROI 의 pre-pad 입력 버퍼를 만들 때 **각 행을 4바이트 배수로 맞춰**
주십시오. 행 길이가 `98 × 3 = 294` 바이트인데 4의 배수가 아니라서,
PL 이 이 버퍼를 **바이트 단위로밖에 못 읽습니다.**

## 왜 필요한가 (전부 실측)

conv0 는 프레임의 **19.4%** (150,894 / 777,678 사이클) 입니다.
행당 비용을 차분법으로 분해했습니다 — 형상을 바꿔 가며 세 번 cosim 했습니다.

| 형상 (pre-pad) | 사이클 |
|---|---|
| 98×98 (정본) | 150,894 |
| 50×98 | 76,253 |
| 98×50 | 85,973 |

→ **Total = 행수 × (14.09 × img_w + 174) + 1,612**

열당 14.09 의 내역 (`READ_ROW` 의 AXI 읽기만 제거한 스로틀 빌드로 분리):

| 항목 | 열당 사이클 | |
|---|---|---|
| `READ_ROW` | **4.5** | 3반복 × 1.5 — **바이트 단위 읽기** |
| `COL_GROUP` | 4.0 | 4반복 × 1.0 (연산) |
| `WRITE_ROW` | 5.6 | 4반복 × 1.4 |
| 합 | **14.1** | 실측 14.09 ✓ |

**conv0 의 비용은 연산이 아니라 AXI 트랜잭션입니다.** 연산 루프만 반복당
1.0 이고 읽기·쓰기는 1.4~1.5 입니다.

비교로, 같은 AXI 를 쓰는 `maxpool_engine` 은 **워드(4바이트) 단위로 읽어서
반복당 정확히 1.0** 입니다. 차이는 하드웨어가 아니라 **데이터 레이아웃**입니다.

## 무엇을 바꿔야 하나

지금: 행 `r` 의 시작 오프셋 = `r × 294`. 294 는 4의 배수가 아니므로 행마다
시작 위상이 2바이트씩 어긋납니다 → PL 이 `pack4_t*`(32비트) 포인터로 못 읽습니다.

요청: **행 스트라이드를 296 바이트로** (행 끝에 2바이트 패딩, 값 무관).

| | 지금 | 요청 후 |
|---|---|---|
| 행 스트라이드 | 294 B | **296 B** |
| 버퍼 전체 | 28,812 B | **29,008 B** (+196 B, +0.68%) |
| 행 시작 정렬 | 2바이트 위상 어긋남 | **4바이트 정렬** |

버퍼 시작 주소도 4바이트 정렬이어야 합니다(대개 이미 만족).

## 그러면 PL 은 무엇을 하나

`conv0_engine` 의 `ifmap` 포인터 타입을 `act_t*` → `pack4_t*` 로 바꾸고
`READ_ROW` 를 워드 단위로 돌립니다. **반복이 열당 3 → 0.75 로 줄어**
약 28,000~32,000 사이클이 절약됩니다.

- conv0: 150,894 → **약 119,000~123,000** (−19~21%)
- 프레임: 777,678 → **약 746,000~750,000** (−3.6~4.1%)
- FPS@10ROI: 12.86 → **약 13.4**

⚠️ **이 숫자는 추정입니다.** 스로틀은 "얼마 벌 수 있나"만 증명하지 "무엇을
고치면 벌리나"는 증명하지 않습니다. 계약이 바뀌면 PL 이 구현하고 cosim 으로
확정합니다.

## 왜 PL 단독으로 못 하나

두 가지를 이미 확인했습니다.

1. **`max_widen_bitwidth=32` 프라그마는 무효**입니다 — 코드 주석에 이전
   시도가 기록돼 있고, 1바이트 정렬에 막힙니다. 포인터 타입을 바꿔야 합니다.
2. **PL 단독 우회는 가능하지만 하지 않기로 했습니다** — 이미지 전체를 워드
   스트림으로 읽고 위상(0/2)을 시프트로 흡수하는 방법이 있으나, 현재 배치가
   **Slice 98.32%** 이고 언팩 경로를 추가하면 마감된 타이밍을 흔듭니다.
   프레임 4% 를 위해 감수할 위험이 아닙니다.

## 안 해도 되는 경우

**요청을 거절하셔도 프로젝트는 안 멈춥니다.** 현재 12.86 FPS 로 요구
(5~7 FPS)를 이미 충족합니다. 이 요청은 **젯슨 연동 시의 엔드투엔드 여유**를
버는 것이 목적입니다.
