# ROI 개수별 처리량 실측 및 N=10 환산

작성: 2026-08-24  
대상: Jetson Nano 5W + Arty Z7-20 DB + 동기식 TCP ROI 분류

## 1. 측정 조건

- Jetson Nano 전력 모드: 5W
- 입력: 카메라 640x360
- proposal: YOLOv8n, 최대 ROI 10개
- ROI: 96x96 RGB
- 처리 순서: `YOLO -> crop -> ROI별 TCP 왕복 -> MJPEG publish`
- Arty: 96x96 INT8 분류기
- 통신: ROI 요청 한 건의 응답을 받은 뒤 다음 ROI를 보내는 동기식 구조

## 2. 전체 세션

```text
측정 시간             708.00 s
완료 프레임           15,268
분류 ROI              33,634
평균 ROI/frame        2.20
응답 오류             0
```

주요 단계 중앙값:

| 단계 | 중앙값 |
|---|---:|
| YOLO proposal | 25.361 ms/frame |
| crop+prepare | 0.533 ms/ROI |
| Jetson-Arty TCP 왕복 | 8.262 ms/ROI |
| MJPEG publish | 0.355 ms/frame |

## 3. ROI 개수별 E2E 실측

| 프레임당 ROI | 표본 수 | 프레임 중앙값 | 실측 FPS |
|---:|---:|---:|---:|
| 0 | 1,559 | 31.870 ms | 31.38 |
| 1 | 6,766 | 34.955 ms | 28.61 |
| 2 | 1,872 | 43.852 ms | 22.80 |
| 3 | 965 | 53.253 ms | 18.78 |
| 4 | 454 | 61.285 ms | 16.32 |
| **5** | **3,511** | **70.094 ms** | **14.27** |
| 6 | 129 | 79.052 ms | 12.65 |
| 7 | 12 | 88.230 ms | 11.33 |

`N=5`는 실제 객체 5개를 배치한 E2E 실측이며, 3,511프레임에서 오류 없이
측정했다.

## 4. N=10 E2E 환산

### 4.1 단계별 지연 합산

프레임당 한 번 실행되는 비용과 ROI마다 반복되는 비용을 분리한다.

```text
T(N) = proposal + N x (crop + TCP RTT) + MJPEG
```

`N=10`을 대입하면:

```text
25.361 + 10 x (0.533 + 8.262) + 0.355
= 113.666 ms/frame

FPS = 1000 / 113.666
    = 8.80 FPS
```

### 4.2 N=1~5 실측 추세로 교차 검산

`N=1~5` 프레임 중앙값에 선형 회귀를 적용하면 다음 관계가 나온다.

```text
T(N) = 26.375 + 8.771 x N  [ms]
```

따라서:

```text
T(10) = 114.086 ms/frame
FPS   = 8.77 FPS
```

이 식은 환산에 사용하지 않은 `N=6`과 `N=7`도 각각 약 `79.0 ms`, `87.8 ms`로
예측한다. 실제 중앙값 `79.052 ms`, `88.230 ms`와 가까워 현재 동기식 구조가
ROI 개수에 따라 거의 선형으로 증가한다는 것을 확인할 수 있다.

두 방법의 결과 차이는 약 0.4%다.

| N=10 환산 방법 | 처리시간 | FPS |
|---|---:|---:|
| 단계별 지연 합산 | 113.666 ms | 8.80 |
| N=1~5 실측 회귀 | 114.086 ms | 8.77 |
| **대표값** | **약 114.0 ms** | **약 8.8 FPS** |

## 5. PL 및 PS+PL 처리량 환산

아래 값은 전체 카메라 파이프라인이 아니라 각 범위의 ROI 실행시간만 10배한
처리량이다.

| 범위 | ROI 1개 실측 | ROI 10개 환산 | 환산 FPS |
|---|---:|---:|---:|
| PL 실행 | 6.614 ms | 66.140 ms | 15.12 |
| PS 전처리+PL+후처리 | 6.877 ms | 68.770 ms | 14.54 |
| 전체 E2E | 단계별 합산 | 약 114.0 ms | 약 8.8 |

Cosim 수치를 비교할 때도 동일한 범위를 맞춰야 한다. 순수 PL Cosim 시간은
첫 번째 행의 실보드 PL 시간과 비교하고, 카메라·YOLO·TCP가 포함된 E2E FPS와
직접 비교하지 않는다.

## 6. 환산 기준과 해석

`ROI 1개 시간 x 10`은 PL 또는 PS+PL처럼 모든 비용이 ROI마다 반복되는 범위에는
적절하다. 전체 E2E에서 `N=5` 처리시간을 단순히 두 배하거나 `N=1` 프레임 시간을
10배하면 YOLO proposal과 MJPEG 같은 프레임 고정비까지 중복 계산하므로 부정확하다.

따라서 전체 E2E의 N=10은 다음 두 근거를 사용한다.

1. 프레임 고정비와 ROI 반복비를 분리한 단계별 합산
2. 실제 N=1~5 중앙값의 선형 추세 및 N=6~7 교차 확인

N=10 장면을 직접 실행한 값은 아니므로 발표 자료에는 반드시 `환산` 또는
`실측 기반 추정`으로 표시한다.

## 7. 팀 공유용 요약

```text
약 114.0 ms/frame, 약 8.8 FPS

환산 근거:
단계별 합산 8.80 FPS, N=1~5 실측 회귀 8.77 FPS로 약 0.4% 이내 일치

가속기 범위만 환산:
PL 15.12 FPS, PS+PL 14.54 FPS (ROI 10개 기준)
```
