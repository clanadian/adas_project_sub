## 통제 비교 — FPS·confidence (같은 세션, 같은 카메라 조건)

같은 날 이어서 DB → EB 순으로 재부팅해 측정했다(카메라 위치·조명·피사체
변경 없음, 둘 다 confidence_ppm 구현 후, 각 60초 라이브 카메라 구간).
수치는 `ps_classifier_server`의 `ADAS_PS_CSV`/세션 요약 그대로다 — 가공 없음.

| 항목 | DB | EB |
| --- | --- | --- |
| 요청 수 (오류) | 979 (0) | 1164 (0) |
| 수신 간격 포함 처리량 | 14.83 ROI/s | 14.64 ROI/s |
| 보드 처리량 상한 (server_us 기준) | **145.67 ROI/s** | **79.93 ROI/s** |
| PL 실행 시간 (mean / min / max) | 6.604 / 6.525 / 6.644 ms | 12.255 / 12.091 / 12.360 ms |
| 서버 총 처리 시간 (mean) | 6.865 ms | 12.511 ms |
| confidence_ppm (mean / min / max) | 85.1% / 26.2% / 100.0% | 79.1% / 33.6% / 100.0% |

**수신 간격 포함 처리량이 둘 다 14.6~14.8 ROI/s로 거의 같다는 점이 핵심이다.**
PL 실행 시간은 EB가 DB의 약 1.86배인데(12.255ms vs 6.604ms), 실제 end-to-end
처리량 차이로는 거의 안 나타난다 — 이 조건(ROI 1~2개/프레임)에서는 Jetson
쪽 카메라 캡처(33ms)·YOLO proposal(13.6ms)이 병목이라 보드 처리 속도 차이가
가려진다. 보드 자체의 처리량 상한(145.67 vs 79.93 ROI/s)에서는 그 1.86배
차이가 그대로 보인다 — **가속기 성능 차이는 실재하지만, 지금 파이프라인
구성에서는 Jetson 쪽이 먼저 병목이라 체감 FPS로는 드러나지 않는다.**
ROI 개수가 늘어나거나 Jetson 쪽이 빨라지면(추후 젯슨 단독 실행 비교 항목)
이 차이가 그대로 드러날 것으로 예상한다.

confidence_ppm은 **정확도가 아니라 모델 자신의 softmax 확신도**다 — 실측
라이브 장면에 정답 라벨이 없어 어느 쪽이 "더 잘 맞혔는지"는 이 수치로 판단할
수 없다. 두 모델의 확신도 분포가 비슷한 수준(80%대 평균, 양쪽 다 최댓값
100%까지 찍음)이라는 것만 확인된다.
