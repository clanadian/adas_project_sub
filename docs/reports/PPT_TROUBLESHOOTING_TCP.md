# PPT 전달용 — 통신 지연 개선

## 슬라이드 제목

**빠른 연산을 가로막던 통신 지연 개선**

## 핵심 메시지

FPGA는 빠르게 계산을 끝냈지만 결과를 전달하는 과정에서 불필요한 대기가
발생했다. 전체 시스템의 흐름을 측정해 원인을 찾고, 전송 방식을 개선해 ROI
왕복 지연을 크게 줄였다.

## 슬라이드 본문

### 1. 문제 발견

```text
FPGA 계산은 6.6ms
전체 왕복은 51.6ms
```

계산이 끝난 뒤 약 40ms가 어디에서 소요되는지 알 수 없었다.

### 2. 원인 분석

```text
계산 결과를 여러 조각으로 전송하면서
약 40ms의 불필요한 대기 발생
```

보드 사이의 패킷 흐름을 측정해 연산이 아니라 결과 전달 과정이 병목임을
확인했다.

### 3. 구조 개선

```text
나뉘어 있던 응답 데이터를
하나로 합쳐 전송
```

데이터 내용과 통신 규격은 유지하고 전송 횟수만 줄였다.

### 4. 개선 결과

```text
ROI 왕복 지연
51.6ms  →  9.7ms

약 5.3배 단축
```

FPGA 설계와 비트스트림은 변경하지 않았다.

## 추천 시각화

슬라이드 중앙에 전후 시간 막대 두 개를 배치한다.

```text
개선 전  [ FPGA 계산 6.6ms ][ 불필요한 통신 대기 약 40ms ][ 기타 ]
         ─────────────────────────────────────────────── 51.6ms

개선 후  [ FPGA 계산 6.6ms ][ 통신·기타 ]
         ───────── 9.7ms
```

- 개선 전 막대의 통신 대기 영역은 붉은색으로 표시
- 개선 후 막대는 파란색으로 표시
- `51.6ms → 9.7ms`를 페이지에서 가장 큰 숫자로 배치
- 코드와 패킷 캡처는 본문에 넣지 않음

## 팀적 가치

> 각 파트의 단독 성능에 머무르지 않고 전체 시스템을 측정해, FPGA 외부에
> 숨어 있던 병목을 찾아 개선했다.

발표에서는 다음 세 가지를 강조한다.

- PL·PS·Jetson을 연결한 전체 구간을 함께 측정했다.
- 특정 파트의 추측이 아니라 실제 패킷 흐름으로 원인을 확인했다.
- 통신 규격과 다른 파트의 코드는 유지해 수정 범위를 최소화했다.

## 발표 멘트

> FPGA는 약 6.6ms에 계산을 마쳤지만 전체 왕복에는 51.6ms가 걸렸습니다.
> 보드 사이의 데이터 흐름을 확인한 결과, 계산 결과를 여러 조각으로 보내는
> 과정에서 약 40ms의 불필요한 대기가 발생하고 있었습니다. 응답 데이터를
> 하나로 합쳐 전송하도록 개선했고, FPGA를 변경하지 않고 왕복 지연을
> 9.7ms까지 줄였습니다.

## 발표자 참고 — 기술적 근거

아래 내용은 본문 슬라이드에 넣지 않고 질문 대응에만 사용한다.

### 실제 원인

PS가 응답 헤더 20B와 결과 12B를 두 번의 `send()`로 전송했다. 첫 번째 작은
데이터의 ACK가 오기 전에 두 번째 전송이 발생하면서 Nagle 알고리즘과 Jetson의
delayed ACK가 결합했고, 두 전송 사이에 약 40ms의 대기가 생겼다.

### 확인 방법

RPi에서 `tcpdump`로 Jetson–Arty TCP 패킷을 측정했다.

```text
Arty → Jetson  응답 헤더 20B
                 │
                 │ 약 40ms 대기
                 ▼
Arty → Jetson  결과 12B
```

PL 연산은 약 8ms 시점에 이미 끝났으며, 결과 12B가 첫 응답으로부터 약 40ms 뒤에
전송되는 것을 확인했다.

### 적용한 조치

- 임시 조치: `TCP_NODELAY`와 Jetson `TCP_QUICKACK`
- 최종 조치: 헤더와 결과를 32B 버퍼로 합쳐 한 번의 `send()`로 전송
- 와이어의 바이트 순서와 프로토콜은 유지
- PL 및 비트스트림 변경 없음

### 표현 시 주의사항

- `FPGA가 5.3배 빨라졌다`고 표현하지 않는다.
- 정확한 표현은 **TCP ROI 왕복 지연이 약 5.3배 줄었다**이다.
- 51.6ms와 9.7ms는 같은 보드·비트스트림·카메라 조건에서 측정한 ROI 왕복
  중앙값이다.
