## 1. 실행 조건

- Jetson Nano: **5W 전력 모드**, GPU 614.4 MHz
- 카메라 입력: 640x360
- 후보 탐지: YOLOv8n, 최대 ROI 10개
- FPGA 분류 입력: 96x96 RGB ROI
- FPGA: Arty Z7-20 DB, 96x96 INT8 분류기
- 통신: Jetson이 ROI 한 건을 보내고 Arty 응답을 받은 뒤 다음 ROI를 보내는
  동기식 TCP 구조
- 통합 경로:

```text
카메라
  -> Jetson 후보 탐지·ROI 생성
  -> TCP
  -> Arty PS 전처리
  -> PL CNN 분류
  -> Arty PS 후처리·안전 판단
  -> UART
  -> TurtleBot 제어 및 통합 UI
```

## 5. 구간별 해석

### 5.1 Jetson

- proposal 중앙값은 25.361 ms/frame이다.
- ROI 한 개의 crop·전처리는 0.533 ms로 작다.
- TCP 왕복은 ROI당 8.262 ms이며, 이 안에 Arty의 PS 전처리·PL 실행·PS
  후처리와 네트워크 왕복이 포함된다.
- 전체 평균 FPS 21.56은 평균 ROI가 2.20개인 혼합 장면의 값이다. 객체 5개
  조건은 ROI별 표의 14.27 FPS를 사용해야 한다.

### 5.2 Arty PS·PL

| 구간 | 평균 |
|---|---:|
| PS 전처리 | 0.132 ms/ROI |
| PL CNN | 6.614 ms/ROI |
| PS 후처리 | 0.126 ms/ROI |
| 서버 전체 | 6.877 ms/ROI |

Arty 서버 시간의 약 96%가 PL 실행이다. 평균 기준 처리량 상한은 145.42 ROI/s다.
`pl_run` 최대 11.257 ms와 TCP 왕복 최대 215.663 ms는 간헐 지연이지만, 평균과
p95가 안정적이고 오류가 없어 지속적인 성능 저하로 보이지 않는다.

### 5.3 N=10 환산

이번 장면에서는 N=7까지 직접 관측됐다. N=10은 실측이 아니라 다음 식으로
환산한다.

```text
T(N) = proposal + N x (crop + TCP RTT) + MJPEG
T(10) = 25.361 + 10 x (0.533 + 8.262) + 0.355
      = 113.666 ms
FPS   = 8.80
```

N=1~5 실측 중앙값의 선형 회귀 결과도 8.77 FPS로 약 0.4% 이내에서 일치한다.
따라서 발표에는 **N=5 14.27 FPS는 실측**, **N=10 약 8.8 FPS는 실측 기반
환산**으로 구분한다.

상세 계산은 `ROI_COUNT_SCALING_REPORT_2026-08-24.md`에 기록했다.

## 6. 8월 21일 측정과 비교

8월 21일과 24일의 통합 파이프라인 측정은 모두 Jetson Nano **5W 모드**에서
수행했다. 별도로 수행한 Jetson GPU 비교 실험만 MAXN 모드를 사용했으므로,
아래 차이를 전력 모드 변화로 해석하지 않는다.

| 항목 | 8월 21일 | 8월 24일 | 변화 |
|---|---:|---:|---:|
| 평균 ROI/frame | 1.01 | 2.20 | +1.19 |
| 전체 FPS | 28.58 | 21.56 | -24.6% |
| proposal 중앙값 | 17.350 ms | 25.361 ms | +46.2% |
| crop 중앙값/ROI | 0.365 ms | 0.533 ms | +46.0% |
| TCP RTT 중앙값/ROI | 8.236 ms | 8.262 ms | +0.3% |
| PL 실행 평균/ROI | 6.617 ms | 6.614 ms | -0.05% |
| Arty 서버 평균/ROI | 6.881 ms | 6.877 ms | -0.06% |
| 분류 응답 오류 | 0 | 0 | 동일 |

### 6.1 바뀌지 않은 부분

- PL 실행시간은 6.617 ms에서 6.614 ms로 사실상 동일하다.
- Arty의 PS 전처리·PL·후처리 전체 시간도 6.881 ms에서 6.877 ms로 동일하다.
- TCP 왕복 중앙값은 8.236 ms에서 8.262 ms로 측정 오차 수준의 차이다.
- 따라서 FPGA 비트스트림, Arty 서버 및 Jetson-Arty 통신에서 지속적인 성능
  저하는 관찰되지 않았다.

### 6.2 전체 FPS가 달라진 주된 이유

8월 21일에는 프레임당 평균 ROI가 1.01개였지만 이번에는 2.20개였다. 현재
클라이언트는 각 ROI의 응답을 받은 뒤 다음 ROI를 보내므로, ROI가 늘 때마다 약
8.3 ms의 TCP 왕복 비용이 순차적으로 추가된다. 전체 FPS가 28.58에서 21.56으로
낮아진 것은 주로 장면의 ROI 수가 증가했기 때문이다.

이번 측정에서는 실제 ROI 5개 프레임을 3,511개 확보해 **N=5에서 14.27 FPS**를
새롭게 실측했다. 전체 평균 FPS보다 이 값이 객체 5개 조건을 설명하는 데 더
적합하다.

### 6.3 캡처 대기시간 차이

캡처 중앙값은 8월 21일 6.223 ms에서 이번 0.001 ms로 줄었다. 카메라 자체가
빨라졌다는 의미는 아니다. 이번에는 다수 ROI를 처리하는 동안 백그라운드 캡처
스레드가 다음 최신 프레임을 준비하므로, 메인 처리 루프가 카메라를 기다릴
필요가 거의 없어진 결과다.

### 6.4 proposal 시간 차이

proposal 중앙값은 17.350 ms에서 25.361 ms로 늘었다. 두 실행 모두 5W
모드였고, 최근 안전 제어 로직 변경은 Arty PS에서 수행되므로 proposal 연산과
직접 관련이 없다.

현재 로그만으로는 다음 가능성을 구분할 수 없다.

- `jetson_clocks` 적용 상태 또는 순간 클럭 차이
- 보드 온도와 thermal throttling
- 측정 당시의 동시 GPU·CPU 부하
- 8월 21일 배포 바이너리나 실행 환경과의 차이

따라서 proposal 차이의 원인은 미확정으로 기록한다. 재비교할 때는 같은 5W
모드에서 `jetson_clocks --show`, 온도, 실행 명령, 엔진 파일 해시를 함께
기록해야 한다.

## 8. 종료 및 현재 상태

- 위 Jetson 측정 세션은 `SIGINT`로 정상 종료되어 요약이 출력됐다.
- 이는 **측정 세션 종료 기록**이며 세 보드 전체 전원 종료 기록은 아니다.
- 보고서 작성 시점에는 후속 실험용 서버를 유지했으므로, 현재 서버가 켜져
  있다는 사실과 모순되지 않는다.
- Arty와 TurtleBot을 강제 종료하거나 재부팅하지 않았다.

## 9. 로그 보존 주의사항

따라서 종료 순간 출력된 원문은 이 문서와
`ROI_COUNT_SCALING_REPORT_2026-08-24.md`에 보존했다.

다음 측정부터는 세션마다 파일명을 분리한다.

```text

```

양쪽 로그의 시작·종료 시각과 요청 수가 일치할 때만 동일 세션 결과로 묶는다.

## 10. 발표용 한 줄 요약

> Jetson Nano 5W와 Arty Z7-20을 연결한 실제 객체 5개 조건에서 14.27 FPS를
> 기록했으며, 33,634건의 FPGA 분류 요청을 오류 없이 처리했다. 8월 21일과
> 비교해 FPGA 및 통신 성능은 동일했고, 전체 FPS 차이는 주로 프레임당 ROI 수
> 증가에서 발생했다.
